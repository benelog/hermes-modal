# KakaoTalk 북클럽 대화 요약

## Trigger

사용자가 카카오톡 대화방 요약을 요청할 때 사용한다. 예: "카카오톡 ABC방 요약해줘",
"아카라카북클럽 오늘 대화 요약", "카톡 북클럽 3일치 요약". 수집 대상 방은 하나뿐이므로
방 이름 표현이 정확하지 않아도 이 방을 요약하면 된다.

## Procedure

1. 요청에서 기간을 추출한다. "오늘"/언급 없음 → `1day`, "3일치"/"3일" → `3day`,
   "이번주" 등 모호하면 `7day`. 시간 단위는 `12h`처럼 쓸 수 있다.
2. 조회 헬퍼를 실행해 수집된 메시지를 가져온다(기간은 추출값으로 치환):
   ```bash
   python /root/.hermes/scripts/kakao_fetch.py --since 1day
   ```
3. 출력 JSON을 파싱한다. 형태:
   - `ok` (bool)
   - `count` (int)
   - `messages`: 각 항목에 `sender`, `text`, `client_time`(카톡에 보였던 시각),
     `received_at`(수집 시각, UTC)
4. `ok`가 false거나 `count`가 0이면, 해당 기간에 수집된 메시지가 없다고 한국어로 알리고,
   디바이스에서 방을 열어 스크롤해야 수집된다는 점을 한 줄로 덧붙인다.
5. 메시지가 있으면 한국어로 간결하게 요약한다.
   - 기본 응답은 Telegram 친화적으로 Markdown을 써도 된다: 제목 `## 아카라카북클럽 대화 요약`, 첫 줄 `기준: 최근 <기간> · <count>건`, 핵심 화제 3~6개, 결정/약속/일정 강조.
   - 단, Modal `kakao_summarize` 엔드포인트처럼 결과가 그대로 카카오톡 방에 전송되는 경우에는 평문으로 작성하고 Markdown 헤더(`#`)나 굵게(`**`) 같은 서식을 쓰지 않는다.
6. 요약만 답장한다. 원문 메시지를 그대로 나열하지 않는다.

## Constraints

- 정상 요약 요청에는 되묻지 말고 바로 수행한다.
- 수집된 메시지(`messages`)만 근거로 삼고 내용을 지어내지 않는다.
- 동일한 본문이 짧은 시간 안에 여러 sender로 중복 수집되고 그중 하나가 요청자/내 닉네임처럼 보이면 Android 접근성 오수집 가능성이 있다. 이 경우 요청자/내 닉네임 발화로 단정하지 말고, 같은 본문의 다른 sender를 우선하거나 sender 불명/중복 수집으로 취급한다.
- 사진/스티커/이모티콘은 `[사진]` 등으로 들어올 수 있으니 텍스트 위주로 요약한다.
- 메시지 유실 가능성(디바이스가 방을 연 범위만 수집)을 전제로, 단정적 표현을 피한다.
- 기간(`since`)은 메시지 "전송 시각"이 아니라 "수집 시각" 기준이다. 즉 오래된 메시지를
  오늘 처음 스크롤해 수집했다면 "오늘" 요약에도 포함될 수 있다. "지난 N일 수집분"으로 이해한다.
- Modal `kakao_summarize` 엔드포인트 입력처럼 메시지가 `[발신시각 KST] 보낸이: 내용` 형식으로 주어지면, 발신시각은 MM/DD 또는 MM/DD HH:MM 형식이다. `~`로 시작하는 시각은 실제 발신시각이 아니라 수집시각 대체값이므로 너무 정밀하게 단정하지 않는다.
- 북클럽 방 요약에서는 대화 중 언급·추천된 책을 먼저 다룬다. 책 제목, 저자, 추천한 사람, 간단한 맥락이 확인되면 함께 적고 확인되지 않으면 지어내지 않는다. 책 언급이 없으면 이 부분은 생략한다.
- 나머지 화제는 대화에 등장한 순서대로 주제별로 정리한다. 각 주제의 대략 시각을 입력의 `[시각]` 기준으로 붙일 수 있지만, 시각 정보가 없거나 `~` 수집시각뿐이면 생략하거나 불확실성을 드러낸다.
- Modal `kakao_summarize` 엔드포인트는 공유 URL 목록을 요약 뒤에 별도로 덧붙인다. 이 경우 요약 본문에는 URL 원문을 반복 나열하지 말고, 어떤 맥락에서 공유됐는지만 언급한다.
- 카카오톡 방으로 바로 전송되는 요약은 그룹 채팅 메시지 한 개에 적당한 길이로 작성하고, 설명/머리말 없이 요약 본문만 출력한다.
